Vera Rubin · Native LUT-B · Accuracy first

Can Vera Rubin run accurate 3-bit LLM inference?

We study one question: can Rubin's native LUT-B instruction run 3-bit model weights and 3-bit KV cache without destroying model quality?

Answer: yes—but only with the right quantizer. Calibrated non-uniform codebooks and scales keep the quality loss bounded. Naive 3-bit quantization collapses. The algorithm, not the bit width alone, decides whether INT3 works.

Experiment 1 — 3-bit weights

Does native W3A8 preserve language-model quality across three architectures?

Model · 8K WikiText-2 BF16 PPL / KL₅₀ Best measured native W3A8 Native uniform W3A8
Qwen3-4B 9.447 / 0 11.538 / 0.23758 91.618 / 2.26101
Gemma4-12B 6.479 / 0 7.842 / 0.36278 10,070.909 / 7.32568
MiniMax-M3 routed experts 5.303 / 0 6.124 / 0.30928 640,419 / 12.17143

Qwen and Gemma use H64 + GPTQ; MiniMax uses RMS²-weighted Lloyd–Max with two-K32 scales. Every reported quantized GEMM above runs through the native Rubin LUT-B MMA.

Result: 3-bit weights are viable, but a naive codebook can be orders of magnitude worse.

Result: from PPL, 3-bit KV is practical when the codebook and scale are controlled. Uniform INT3 is not a usable baseline.

Why these are real Rubin results

Physical payloads Weights and cached K/V are stored as 3-bit indices, an 8-value E4M3 LUT, and scales—not dense BF16 tensors.
Native instruction The kernel issues tcgen05.mma…decompress::lut::b; decompression happens inside the MMA.
No simulated fallback Published MiniMax runs report sim_fallback_gemms = 0. Simulation and hardware agree on rankings and collapse.

Scope

This is an accuracy study, not an optimized throughput claim. The current kernel is deliberately correctness-first. Faster scheduling, batching, and pipelining are engineering work, not evidence needed for the quality result above.
